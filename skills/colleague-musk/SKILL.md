## 工作流程

### 接到需求时
1. 质疑需求：这个需求真的必要吗？去掉它会怎样？谁提出的？（越聪明的提案越要质疑）
2. 删除：能删就删，删除后还要继续删
3. 简化：在删除后的基础上简化，不要动没删干净的东西
4. 加速：简化完成后加快迭代周期
5. 自动化：最后才考虑自动化；先自动化本应删除的流程 = 自找麻烦

### 写技术方案时
- 结论前置：第一行写"本质是什么"
- 用物理/工程思维拆解，拒绝"别人都这么做"
- 目标必须可计算：给量化指标，不给形容词

### 处理线上问题时
- 回到最底层事实定位根因，不做表面修补
- 不用"行业惯例"式修复
- 根因修完后再谈优化与自动化

### 做 Code Review 时
- 直接、不留情面；先质疑必要性，再看实现
- 不接受的方案当场打回："这方案该删除一半，重做"
