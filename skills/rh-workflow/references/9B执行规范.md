# 9B RH 执行规范（无漂移宪章）

> 本宪章是 9B 跑 RunningHub API 的**唯一行为准则**。违反任一条 = 违规 = 立即停止并上报 DeepSeek。
> 核心：RH API 是最简单的机械程序，**不需要创造，只需要照做**。

## 1. 唯一入口（只准用这两个，禁止写新脚本）

```bash
cd "<RH_Workflow_Api 脚本目录>"   # 台式机示例：E:\Harness Workspace\Local_LLM\RH_Workflow_Api

# 单任务
python run_i2v_workflow.py ...

# 批量
python batch\run_batch.py --csv batch\任务清单.csv
```

❌ **禁止**：自己写新脚本（如 run_xxx.py）、改写现有脚本、发明新命令。

## 2. 允许的参数白名单（run_i2v_workflow.py）

| 参数 | 说明 |
|------|------|
| `--image <路径>` | 首帧图（绝对路径，Windows 反斜杠） |
| `--prompt "<提示词>"` 或 `--prompt-file <txt>` | 提示词；长提示词用文件 |
| `--duration <秒>` | 时长 |
| `--resize-max 1280` | **必须带**：最长边缩到1280，不裁剪 |
| `--output-dir <目录>` | 输出目录 |
| `--json` | 机器输出 |
| `--check` | 免费自检（提交前必跑） |
| `--image-name openapi/xxx.png` | 复用已上传图（可选） |

❌ **不存在的参数**（用了就是漂移）：`--submit`、`--task_id`、`--first_frame_path`、`--node` 等——脚本 argparse 没有就是没有。

## 3. 流程铁律（顺序不许乱）

1. **先 `--check`**（免费）：Key + 工作流可用才继续
2. **`--resize-max 1280`**：参考图/三视图**绝不裁剪**，只缩放
3. **提交**（= 花钱，参数核对三遍：图路径 / 提示词 / 时长）
4. **轮询与下载交给脚本**：❌ 禁止手写轮询循环（9B 手写曾因 `{el//60:02d}` float 崩溃，任务提交后无人轮询 = 烧钱事故）；如需接管，用 `run_workflow_api.RunningHubClient`

## 4. 提示词铁律

- 开头必须写：`第0帧起画面即为动态场景，禁止参考图版面/三视图/多视角面板/文字/白底站姿停留，人物从第一帧起连续运动`
- 结构：人物锁定 → 场景 → 动作（进行时动词）→ 运镜 → 风格
- 中文即可；参考 `提示词库\picx\picx-分卷\minimax-h3.md` 和 `Vault\手动记录 H3 提示词.md`

## 5. 失败协议（禁止盲目重试）

- 报错 → **不重试** → 写 `batch\issues\<任务id>.md`（含清单行/错误原文）→ 等 DeepSeek 诊断
- 一次性偶发（如 VRAM grow failed）最多重试 1 次

## 6. 状态查询

- 任务状态**只信 API**：`POST /openapi/v2/query`（body: taskId）
- 网页工作台显示滞后/空白**属正常**，不误判"卡住"、不重复提交
